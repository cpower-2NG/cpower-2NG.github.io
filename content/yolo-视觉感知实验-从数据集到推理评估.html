YOLO 视觉感知实验：从数据集到推理评估

在这台机器上跑 YOLO 的动机很实际：抓取流程需要一个能把螺丝、方块从桌面上找出来的视觉环节。我拿 COCO10（从 MS COCO 里截取的 10 类子集）当统一数据集，从环境搭建一路走到视频流推理，核心结论先放在前面——YOLOv8n 训练 50 轮约 35 分钟（GPU）收敛，验证集 mAP@50 大约 0.55，单图推理在 10 毫秒量级；用在仿真环境的常规目标检出上够用，但小目标、遮挡和极端光照仍然是明显的短板。

这篇记录走一遍的完整过程：原理、环境、数据、训练、推理与评估，以及中途踩到的坑。

YOLO 核心原理

YOLO（You Only Look Once）是一种单阶段目标检测算法。其核心思想可概括为：将整张图像输入一个神经网络，单次前向传播即可同时预测所有物体的边界框位置和所属类别。相比需要分步执行"候选区域提取 → 分类"的传统两阶段方法，YOLO 将检测建模为端到端的回归任务，推理速度达到实时级别（毫秒级），非常适合机器人等对延迟敏感的场景。

YOLO 系列自 2016 年提出以来迭代了多个版本（v1 → v8 → v10 → v11 等），这里用工程生态最成熟的 YOLOv8。下面从检测问题的本质出发，展开它的工作机制。

目标检测问题的本质

目标检测需要同时回答两个问题：

  • 定位（where）：物体在图像的什么位置？
  • 分类（what）：这个物体是什么类别？

传统方法将这两个问题拆成串行步骤：先用滑动窗口或区域提议算法扫描全图，找到"可能有物体"的候选区域，再对每个区域单独运行分类器。计算量随候选区域数量线性增长，难以实时。

YOLO 的设计出发点是：将检测重新定义为一个单一的回归问题——直接从输入图像像素映射到边界框坐标和类别概率，中间不经过"区域提议 → 分类"的分步流水线。

图 1 YOLO 单阶段检测：输入图像经过一次神经网络前向传播，同时输出所有物体的边界框和类别

网格划分与单次前向传播

YOLO 将输入图像划分为 S×S 的网格（grid）。每个网格单元负责预测中心点落在该单元内的物体。单次前向传播后，每个网格单元输出：

  • B 个边界框（每个包含 x,y,w,h 和置信度 C）
  • K 个类别概率

整张图的预测结果是一个 S×S×(B×5+K) 的张量。以 YOLOv8 在 640×640 输入下为例，最终输出约 8400 个候选框。

这个设计的核心效果是：无论图像中有多少物体，计算量基本恒定——不像两阶段方法随候选区域数线性增长。

边界框的归一化坐标表示

YOLO 输出的边界框采用中心点归一化坐标：

class_id   x_center   y_center   width   height
   0        0.5234     0.4120    0.0875   0.0650
  • x_center, y_center：框中心在图像中的相对位置（0∼1，相对于图像宽高）
  • width, height：框宽高（同样归一化到 0∼1）
  • class_id：类别编号，从 0 开始

归一化使坐标与图像分辨率解耦，模型可在任意尺寸输入上训练和推理。

置信度与 NMS 后处理

每个边界框附带一个置信度分数（confidence score）：

confidence=P(object)×IoUpredtruth​

其中 IoU（Intersection over Union，交并比）是衡量两个边界框重叠程度的指标，定义为两框交集面积除以并集面积。直观理解：IoU = 1 表示两框完全重合，IoU = 0 表示完全不重叠。因此置信度综合了两个信息——"框内很可能有物体"且"框的位置比较准"。

推理时实际使用类别条件概率：

P(classi​∣object)×P(object)×IoU

后处理分两步：

  1. 置信度过滤：丢弃置信度低于阈值（如 0.25）的框
  2. 非极大值抑制（NMS）：对同一物体的多个重叠框，只保留置信度最高的，抑制 IoU 超过阈值（如 0.7）的重复框

NMS 后每个物体仅保留一个最优边界框。

核心评估指标：mAP

mAP（mean Average Precision，平均精度均值） 是目标检测的核心指标。理解 mAP 需要先了解两个基础概念：

IoU（Intersection over Union）：预测框与真实框的交集面积除以并集面积，衡量定位精度。

Precision 与 Recall：当一个预测框与某个真实框的 IoU ≥ 阈值且类别正确时，记为 TP（True Positive，正确检测）；没有匹配到真实框的预测框记为 FP（False Positive，误检）；没有被预测框匹配到的真实框记为 FN（False Negative，漏检）。由此定义：

Precision=TP+FPTP​,Recall=TP+FNTP​

改变置信度阈值会产生不同的 (Precision, Recall) 对，连成 P-R 曲线，曲线下面积即为 Average Precision（AP）。对所有类别取平均得到 mAP。

常见两种 mAP 变体：

指标含义用途
mAP@0.5IoU ≥ 0.5 即算正确宽松评估，衡量"是否找到物体"
mAP@0.5:0.95IoU 从 0.5 到 0.95（步长 0.05）取平均COCO 官方标准，严格考察定位精度

不同 mAP@0.5 数值对应的大致表现：

  • 0.9 以上：几乎每个物体都被找到，框的位置也很准
  • 0.5 左右：大多数物体能被找到，但存在一定比例的漏检或定位偏差。这次 COCO10 训练 50 轮后约 0.55，属于典型的入门级结果
  • 0.2 及以下：模型只能稳定检测少数几个"简单"类别，多数类别要么大量漏检，要么框的位置偏差很大。此时需要检查数据质量、增加训练轮数或换用更大模型

实际中，mAP 的高低取决于三个因素：数据质量（标注是否准确、覆盖是否全面）、场景复杂度（目标大小、遮挡程度、类内差异）和模型容量（参数量是否匹配任务难度）。

YOLO 模型训练

下面进入训练：怎么启动、怎么读训练过程中的输出、以及常见异常怎么处理。

训练参数详解

训练的核心调用如下：

from ultralytics import YOLO
model = YOLO('yolov8n.pt')
model.train(data='config/coco10.yaml', epochs=50, batch=16, imgsz=640, device='cuda:0')

通过命令行启动（这次用的 scripts/train.py 就是把上面的逻辑封装起来）：

python scripts/train.py
  --model yolov8n.pt
  --data config/coco10.yaml
  --epochs 50
  --batch 16

各参数的含义与选值建议：

参数含义推荐值说明
--model预训练权重文件yolov8n.pt迁移学习的起点
--data数据集配置文件config/coco10.yaml指定训练集、验证集、类别
--epochs完整遍历数据集的次数50越多越充分，但边际收益递减
--batch每次参数更新使用的样本数16显存不足时报 OOM，降至 8
--imgsz输入图像尺寸（像素）640YOLO 标准输入分辨率
--device计算设备自动检测手动指定 cpu 可强制 CPU 模式

此外，训练脚本内部还启用了早停机制（patience=20）：当验证集 mAP 连续 20 轮没有提升时自动终止训练，避免浪费时间。

训练损失分析与收敛判断

训练过程中自动记录三类核心损失：

  • box_loss（边界框回归损失）：衡量预测框与真实标注框的位置偏差
  • cls_loss（分类损失）：衡量预测类别概率与真实类别的偏差
  • dfl_loss（分布焦点损失）：YOLOv8 特有，辅助边界框概率分布的精细回归

典型的训练过程可分为三个阶段：

阶段Epoch 范围现象含义
快速收敛1-20三类损失快速下降模型从预训练权重快速适配新数据
精细调优20-40损失下降放缓，mAP 逐步提升模型逐步学习数据中的细节特征
收敛稳定40-50损失基本平稳，mAP 微幅波动模型在当前设置下接近性能上限

如果训练结束时损失仍有明显下降趋势，可以适当增加 epochs；如果早停机制在 30 轮左右就触发了，说明模型已充分收敛。

常见训练异常排查

实验过程中可能遇到以下三类高频问题：

问题一：训练损失出现 NaN

现象：训练几个 epoch 后，box_loss 或 cls_loss 突然变为 NaN（Not a Number）。

原因：初始学习率过高，导致梯度爆炸。

解决：降低初始学习率（在 train.py 中增加 lr0=0.001 参数），同时检查数据集中是否存在标注为空的异常样本。

问题二：损失不下降、mAP 很低

现象：训练了 10 个 epoch，损失几乎不变，mAP@0.5 始终在 0.1 以下。

原因：最常见的原因是数据路径配置错误——coco10.yaml 中的 path 字段与实际目录不匹配，导致模型读取不到图像；其次是显存溢出（OOM）导致 batch 内数据损坏。

解决：首先确认 data/coco10/images/train/ 下是否有图像文件；其次检查 coco10.yaml 中的路径是否正确；如果显存不足，将 --batch 降至 8。

问题三：显存溢出（Out of Memory）

现象：训练开始时报 CUDA out of memory。

解决：依次尝试 (1) 减小 batch size：--batch 8；(2) 降低输入分辨率：--imgsz 320；(3) 换用更小的模型如 yolov8n.pt（这里默认就是它）。

python scripts/detect.py

脚本将遍历验证集中的所有图像，逐一完成检测并统一保存到 outputs/detect/ 目录。在 RTX 2060 上实测，对 560 张验证集图像进行批量推理：

视频选材

这里用一段公开的无版权街景视频（约 6 秒，353 帧，1920 × 1080，60 fps，约 2.7 MB），画面是日间的交叉路口，出现 person、car、truck、bicycle 等行人和车辆目标，与 COCO10 的类别高度匹配。素材来自 YouTube 上的无版权街景片段，也可以自己找类似的素材，只要画面里包含 COCO10 十类中的若干类即可。

基本原理

视频流检测的核心思路与单图推理完全一致，唯一的区别在于输入源：不再是一次性读入一张图像文件，而是通过 OpenCV 的 VideoCapture 持续读取视频的每一帧，逐帧送入 YOLO 模型完成推理，再将标注后的画面实时显示或写回视频文件。整个处理流水线由三个环节构成：

（1）帧读取。OpenCV 从视频文件（或摄像头）中逐帧读取图像数据，返回的是与单张图片完全相同的 BGR 格式的 NumPy 数组。这意味着 YOLO 模型不需要任何修改——它接收的仍然是一张张独立的图像。

（2）逐帧推理。将每一帧送入 YOLO 模型，模型完成前向传播后返回该帧中所有检测到的目标（类别、边界框坐标、置信度）。这一过程与 3.6.1 节中的单图推理完全一致，只是循环执行。

（3）结果输出。模型返回的结果通过 OpenCV 绘制到原始帧上，可选择实时弹窗显示（--show），也可将标注后的帧逐帧写入 MP4 文件（默认行为），得到完整的检测结果视频。

检测脚本在 yolo_coco/scripts/detect_video.py，直接用即可。

运行方式

cd yolo_coco
conda activate yolo_coco

# 使用训练好的 COCO10 模型对街景视频进行检测
python scripts/detect_video.py
  --model outputs/train/<时间戳>/weights/best.pt
  --source assets/street_scene.mp4
  --show

各参数含义如下：

  • --model：训练好的模型权重路径（.pt 文件）。
  • --source：输入视频文件路径，或摄像头索引（如 0 表示默认摄像头）。
  • --conf：置信度阈值，低于该值的检测框将被丢弃，默认为 0.25。
  • --show：启用后实时弹窗显示检测画面，按 Q 键可提前退出。
  • --no-save：启用后不保存结果视频，仅用于快速查看效果。

程序运行完成后，结果视频保存在 outputs/detect_video/result.mp4。

检测结果的结构化保存

除了可视化图像和视频外，detect.py 和 detect_video.py 还自动将检测结果保存为结构化文本格式。在 outputs/detect/ 目录下，每张输入图像对应一个同名的 .txt 文件：

# outputs/detect/000000000001.txt
person 0.85 120 45 380 510
car 0.72 50 200 290 420
bicycle 0.68 400 150 550 380

格式为：类别名称 置信度 左 上 右 下（像素坐标，非归一化）。这种结构化输出便于后续程序化处理，例如统计各类别出现频次、筛选高置信度目标、与其他模块对接等。

训练-验证曲线对比与过拟合判断

导出训练过程中自动生成的 results.png（参见图 2），观察以下关键信号：

  1. 训练损失 vs 验证损失：如果训练集损失持续下降而验证集损失反而上升，说明模型出现了过拟合——即模型"记住"了训练集的特定样本，而不是学到了通用特征。COCO10 上 50 轮训练通常不会出现过拟合，两条曲线下降趋势基本一致。
  1. mAP 收敛时机：观察 mAP 曲线可以定位模型在哪个 epoch 达到峰值。这次大约在第 40~45 轮接近收敛，之后再训练 mAP 提升非常有限。这说明 50 epochs 对这个数据集是合适的——训练过少欠拟合，过多则浪费时间。
  1. box_loss 与 cls_loss 的相对变化：通常 cls_loss 下降更快、收敛更早，因为分类任务比定位任务更"容易"。如果 cls_loss 很低但 mAP 不高，说明问题出在定位而非分类——可能是标注质量有问题或 NMS 阈值不合适。

逐类 AP 分析与漏检误检归因

COCO10 上不同类别的 AP 差异显著：

类别AP@0.5分析
bus0.761形态方正、特征一致、类内差异小
person0.669样本最多（1592 实例），但姿态、穿着、尺度差异巨大
motorcycle0.619形态特征较明显，样本量中等
car0.589形态较统一，但颜色和角度变化多
cat0.571样本极少（仅 52 实例），但猫的形态在 COCO 中相对一致
bicycle0.560视角变化大，常与 motorcycle 混淆
truck0.534形态多样（货车、卡车差异大），类内一致性低
dog0.527品种多样，形态差异极大
bottle0.422小物体，特征信息少
chair0.266形状、材质、视角差异极大，公认的难检测类别

从上述差异可以总结出三类典型的检测失败场景：

第一类：小目标漏检。画面中距离镜头较远的行人或车辆，由于在图像中占比过小（例如小于 32×32 像素），经 640×640 缩放后特征信息不足，容易被模型漏检。在视频流实验中，远处行人的置信度通常在 0.3 以下甚至完全不被检出。解决方案包括增大输入分辨率（如 1280）、使用针对小目标优化的数据增强策略。

第二类：密集遮挡漏检。当多个同类目标紧密堆叠、互相遮挡时（如拥挤人行道上的行人），被大面积遮挡的目标无法被模型识别——因为 YOLO 仅依赖可见部分的视觉特征。这也是目标检测领域的共性难题。

第三类：相似类别误检。bicycle 与 motorcycle、cat 与 dog 之间由于外观相似，模型偶尔会出现类别混淆。尤其在目标较小、画面模糊时，分类错误的概率明显增大。这反映了基于纯外观特征的分类在细粒度任务上的固有局限。

超参数横向对比实验

控制其他变量不变，仅调整批次大小（batch）和初始学习率（lr0）两个核心超参数，设置多组对照实验，理解超参数对训练结果的影响。

实验方案：在 scripts/train.py 中增加 --lr0 参数支持，分别测试以下组合：

实验组batchlr0预期结果
基准组160.01mAP@0.5 ≈ 0.54
大 batch320.01收敛更平稳，但需要更大显存
小 batch80.01梯度噪声大，收敛可能震荡
高学习率160.05极易 NaN 或不收敛
低学习率160.001收敛慢，50 epochs 可能欠拟合

可以按自己的硬件挑几组实测对比。几个关键结论：

  • 学习率是最敏感的超参数——过大直接导致训练崩溃（NaN），过小导致收敛缓慢
  • batch size 主要影响训练的稳定性和显存占用，对最终精度的直接影响较小（在合理范围内）
  • 默认值 lr0=0.01, batch=16 是 YOLOv8 在大量实验中验证的稳健起点，一般情况下无需调整

结语

这次把 YOLO 从原理到推理的链路完整跑了一遍：环境搭建 → 数据集准备 → 训练 → 推理测试 → 性能分析。走完之后，对几件事有了具体的体感：

  • 网格划分 + 单次前向传播 + 归一化坐标这套设计，是它能做到毫秒级出结果的根因；
  • mAP、Precision、Recall 真正读起来，比只看单个数字更能判断模型坏在哪；
  • 训练里的 NaN、不收敛、OOM 基本都有固定的排查顺序，先降 batch 和分辨率，再换小模型，多数能救回来；
  • 漏检和误检的归因最后都会落回数据：类别样本多少、目标大小、遮挡程度。

落地时的边界

真实场景里 YOLO 的局限也很明显：

  • 极端光照条件：在画面严重过曝或过暗时，模型的检测精度会大幅下降——因为训练数据以正常光照为主
  • 大面积遮挡：当目标被大面积、长时间遮挡时，模型无法仅凭可见部分推断完整目标
  • 细粒度类别区分：对于外观高度相似的类别（如不同品种的狗），YOLO 的识别能力仍然有限
  • 小目标检测：远处的小目标特征信息不足，是 YOLO 乃至所有目标检测器的共性难题

这些不是 YOLO 独有的问题，而是当前视觉感知的普遍边界。知道边界在哪，方案就好设计——比如补光改善光照、多相机覆盖减少遮挡。
